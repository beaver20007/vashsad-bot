# Журнал sha смёрженных PR (main)

Короткая хронологическая лента merge-коммитов в `main`: номер PR, sha
merge-коммита, родители, когда смёржено, кто дал слово на мерж. Подробности
по содержимому каждого трека — в `docs/ORCHESTRATOR.md` (записи по датам);
здесь — только факт мержа для быстрой проверки «что реально доехало до
`main`» без прокрутки всего журнала.

Пополняется по мере мержей. Id пользователей — по правилу docs/ORCHESTRATOR.md
от 27.09.2026 (маскировка `***`+2 цифры или текстовая метка роли).

| #54 | `feat/booking-staff-preview` | `885f18f` | `9e3dc15` + `2ba22ee` | 2026-10-03 09:24 | Beaver → Чат ВашСад → Оркестратор |

`main` на момент составления этого журнала (автономная очередь, трек 5,

мержа.

## Как проверить сходится ли журнал с реальностью

```bash
git log origin/main --format='%h %p %s' --merges
```

Если в выводе есть merge-коммит PR, которого нет в таблице выше (или
наоборот — строка есть, а коммита в `git log` нет) — журнал разошёлся с
`main`, нужно поправить при следующем докс-коммите.

## Как пополнять

После очередного мержа в `main` (по слову Beaver) добавить строку в таблицу:
номер PR, имя ветки, sha merge-коммита (`git log origin/main -1 --format=%h`
сразу после мержа), оба родителя (`%p`), время по МСК, кто передал слово
(штатно — Beaver напрямую или через Чат ВашСад). Старые строки не
переписывать постфактум — журнал, а не живой документ с правками истории
(тот же принцип, что для `docs/ORCHESTRATOR.md`).
