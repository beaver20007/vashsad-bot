## Как проверить сходится ли журнал с реальностью

```bash
git log origin/main --format='%h %p %s' --merges
```

Если в выводе есть merge-коммит PR, которого нет в таблице выше (или
наоборот — строка есть, а коммита в `git log` нет) — журнал разошёлся с
`main`, нужно поправить при следующем докс-коммите.

## Как пополнять

После очередного мержа в `main` (по слову Beaver) добавить строку в таблицу:
номер PR, имя ветки, sha merge-коммита (`git log origin/main -1 --format=%h`
сразу после мержа), оба родителя (`%p`), время по МСК, кто передал слово
(штатно — Beaver напрямую или через Чат ВашСад). Старые строки не
переписывать постфактум — журнал, а не живой документ с правками истории
(тот же принцип, что для `docs/ORCHESTRATOR.md`).
