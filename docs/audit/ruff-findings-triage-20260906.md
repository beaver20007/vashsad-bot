# Ruff findings — категоризация и план волн (2026-09-06)

Контекст: ruff CI подключён в PR #22 (2026-08-26), 350 находок зафиксированы
на момент подключения, ни разу предметно не разбирались с тех пор. Свежий
прогон на сегодня (`ruff check . --statistics`) даёт **те же 350** — код с
момента PR #22 в этих местах не менялся.

Метод: каждая категория правил просмотрена по фактическим находкам
(`ruff check . --select <RULE> --output-format=concise`), не только по
названию правила. Для каждой — открыт хотя бы один реальный файл:строка,
проверено поведение до вывода в "безопасно"/"нужен разбор".

## Итоговая раскладка (350 = 137 механических + 27 требуют разбора + 186 E501)

### Волна 1 — «гигиена импортов» (механически безопасно, 95 находок)
`I001` unsorted-imports (55) + `F401` unused-import (39) + `F811`
redefined-while-unused (1, `handlers/start.py:430` — локальный `import os`
внутри функции затеняет неиспользуемый модульный `import os` на строке 2;
удаление модульного импорта убирает оба предупреждения одним действием).

Проверено индивидуально на предмет «импорт для побочного эффекта» (когда
удаление сломало бы регистрацию роутера/подключение модуля) — **не найдено
ни одного такого случая**: все импорты — обычные неиспользуемые символы,
оставшиеся после рефакторингов (например, `services.scheduler.
_scheduler_instance` в `handlers/poll.py:7` — модульная переменная,
импортированная по значению; даже если бы использовалась, была бы
устаревшей на момент импорта из-за `global`-переприсваивания в
`setup_scheduler()` — лишнее доказательство, что удаление безопасно).
→ **Кандидат на автофикс `ruff check --fix --select I001,F401,F811`.**

### Требует разбора файл-за-файлом — НЕ чинить пачкой (27 находок)

- **`F841` unused-variable (9)** — разобрано поштучно:
  - `services/pdf_generator.py:239,243,247` (`header_row`/`props_row`/
    `desc_row`) — мёртвый черновик: тот же контент задублирован в `tdata`
    четырьмя строками ниже (249-253), которая и используется в `Table(...)`.
    Безопасно удалить — но это не «просто unused var», а следы
    незаконченного рефакторинга, решил не трогать автоматом.
  - `handlers/channel.py:68` (`user`), `handlers/poll.py:39` (`msg`),
    `handlers/watering.py:43` (`t`), `handlers/export.py:216,286`
    (`CREAM`, `EARTH` — неиспользуемые цветовые константы) — похожий
    паттерн, не проверял каждую до конца (не входило в рамки этого
    прохода), но ни одна не выглядит как активный баг.
  - **Не автофиксить**: `ruff --fix` для F841 в основном просто вставляет
    `_` перед именем — не убирает содержательный дублирующий код в
    `pdf_generator.py`. Нужен человеческий рефакторинг, не линт-фикс.
- **`SIM117` multiple-with-statements (6)** — слияние вложенных `with` в
  один. Поведенчески нейтрально в большинстве случаев, но меняет
  структуру блока — решил не пускать автофиксом без просмотра каждого
  (`services/ai.py` x2, `services/scheduler.py`, `services/email_service.py`,
  `services/sms_service.py`, `scripts/pre_deploy_check.py`).
- **`SIM105` suppressible-exception (4)** — `try/except Exception: pass` →
  `contextlib.suppress(Exception)`. Поведенчески эквивалентно, но это
  осознанный молчаливый catch-all в чувствительных местах (`handlers/
  start.py:256`, `handlers/feedback.py:66`, `services/scheduler.py:187,377`)
  — трогать только глядя на каждый case отдельно.
- **`E402` module-level-import-not-at-top (3)** — проверил все три
  (`handlers/saved_replies.py:202`, `handlers/start.py:405`,
  `services/database.py:858`): во всех трёх это **осознанный паттерн
  проекта** — импорт добавлен прямо перед функциональным блоком,
  добавленным отдельным треком поверх уже существующего файла (видно по
  комментарию-заголовку `# ── <фича> ──` перед каждым). Перенести наверх
  мехнически можно, но это будет боевой шум в диффе устоявшегося стиля
  проекта без функциональной пользы — **рекомендую оставить, не чинить**.
- **`E741` ambiguous-variable-name (2)** — `l` в `handlers/booking.py:154`
  и `handlers/export.py:51`. Косметическое переименование, но private —
  зависит от контекста метода, решил не трогать в этом проходе.
- **`F821` undefined-name (2)** — `services/scheduler.py:103,129` — уже
  найдено и задокументировано в предыдущей сессии (2026-08-26, аудит
  152-ФЗ): строковые forward-ref аннотации `slot_dt: "datetime"` при
  локальном (не модульном) импорте `datetime` внутри функции. Безобидно
  в рантайме, известная находка — не новая, не трогаю повторно.
- **`B006` mutable-argument-default (1)** — `tests/load_test.py:14`,
  `headers={}`. Единственная находка с классическим паттерном бага, но
  внутри самой функции `headers` только читается (`session.request(...,
  headers=headers)`), не мутируется — реального бага нет. Дополнительно:
  этот файл — нагрузочный тест **эндпоинтов miniapp** (`/api/health`,
  `/api/plants`, `/api/weather`), а не бота; лежит в этом репо, но не
  часть логики бота. Не трогаю — вне доверенного периметра этого прохода
  (не пересекаться с miniapp).

### `E501` line-too-long (186) — отдельная политика, не волна автофикса
`ruff` **не умеет** автофиксить E501 в принципе (нет `[*]` в
`--statistics`) — только ручной перенос строк. Разбор распределения:
count=186, min=101, max=206, avg=119.5 (лимит в `pyproject.toml` — 100).
Что важно: **46 из 186** превышают 120 символов, **140 из 186** укладываются
в 101-120. Большинство — сообщения бота (кириллица, HTML-теги, эмодзи) и
SQL-запросы в одну строку; искусственный перенос по 100-символьному лимиту
только испортит читаемость этих строк без пользы для качества кода.

**Рекомендация (не выполнено, ждёт решения владельца — это политика, не
автофикс):** поднять `line-length` в `pyproject.toml` со 100 до **120** —
однострочная правка конфига, ноль тронутого кода, закрывает **140 из 186**
находок мгновенно. Оставшиеся 46 (>120 символов, максимум 206) — не гнаться
построчно, оставить как принятый долг или разобрать отдельным узким
проходом, если появится время.
