## ПРОМПТ

Ты работаешь над проектом **MAX Integration** — репликацией существующих Telegram-ботов на платформу мессенджера MAX (max.ru, VK).

### Контекст проекта

Читай `CLAUDE.md` и `PLAN.md` в корне папки — там полный контекст, архитектура и текущий статус спринтов.

### Текущая задача

**Спринт 0 — Разведка**: нужно зарегистрировать бота и получить реальные структуры webhook payload от MAX API.

**Выполни по порядку:**

1. Прочитай `CLAUDE.md`, `PLAN.md` и `src/platforms/max_platform.py`
2. Установи зависимости: `pip install -r requirements.txt`
3. Попроси меня создать бота через @MasterBot в MAX и вставить токен в `.env`
4. После получения токена — запусти `python scripts/test_api.py`
5. Сохрани реальный JSON ответ в `docs/real_api_responses.json`
6. Сравни с документацией на `dev.max.ru/docs-api` и обнови комментарии в `src/platforms/max_platform.py` если структура отличается
7. Зарегистрируй webhook: `python scripts/register_webhook.py <URL>`
8. Отправь тестовое сообщение боту и залогируй входящий payload

### Что НЕ трогать

- Исходники существующих ботов (ВашСад, docraft, VoxSpec) — только читать как reference
- Upstash Redis ключи — только добавлять новые, не изменять существующие
- Supabase схема — только читать

### Правила работы с MAX API

- **Документация MAX врёт** — всегда логировать реальные ответы, не верить доке
- Все запросы через `MaxPlatform._request()` — там есть логирование
- При любой ошибке API — сначала проверить реальный ответ в логах
- MAX — **вторичный канал**, не ломать основной Telegram функционал

### Архитектурный принцип

Адаптер-паттерн: бизнес-логика в `handlers/` работает через `BotPlatform` ABC.
Платформо-специфичный код только в `src/platforms/`.
При переносе хендлера из aiogram — не копировать, а адаптировать через унифицированные модели.

### Как задавать вопросы

Если что-то неясно по структуре существующих проектов — спрашивай, я покажу нужные файлы.
Если MAX API ведёт себя неожиданно — показывай сырой JSON из логов.
